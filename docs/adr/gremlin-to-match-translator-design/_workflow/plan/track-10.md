## Plan of Work

Establish what the correct contract is before changing code — for three of the four failures the question "is the test wrong or the product wrong?" is genuinely open, and answering it wrongly bakes in the mistake. Then fix, then close the hole that let a red suite ride for 117 commits.

0. **Enumerate the actual failure set first (R1).** `./mvnw -pl core test` is not "four scenarios plus units". `core/pom.xml`'s `sequential-tests` execution carries only `<groups>SequentialTest</groups>` — none of the `**/gremlintest/**` exclusion the `default-test` execution has — so the same run drives the core Cucumber runner (`YTDBGraphFeatureTest`) and thirteen other `gremlintest` classes. No artifact on this branch records a full-suite failure list, the repro recipe above is single-class, and the one enumeration on record was wrong ("six problems, not four, and a different set"). Run the full `core` suite, record the complete failure list as an artifact, and size the remaining steps against it. **Triage rule, decided here rather than per-failure later:** a failure is in scope when it is a `YTDBQueryMetricsStrategyTest` scenario or a direct consequence of the `capturedExecutionPlan()` / boundary-lifecycle contracts items 1–3 settle; everything else is pre-existing branch debt, recorded with a disposition and deferred. **If in-scope failures extend materially beyond the four known scenarios — for example the Cucumber runner is red for a boundary-lifecycle reason — that is an ESCALATE, not a step:** the track was planned at ~11–13 files and a broader remediation is a different track.
1. **Settle the `reset()` contract.** Decide whether `AbstractMatchPlanStep` should re-arm from `CLOSED` (matching `YTDBGraphStep`, which re-executes fine) or whether the test's expectation is wrong. This is the one genuine product defect; the decision needs a Decision Record either way.

   **The product-side option means re-create the plan, not restart the closed one (T2).** Mapping `CLOSED` to `REARMED` in the step's own state machine is one line, and it does not work: `AbstractExecutionStep.alreadyClosed` (`:102`) is a private sticky guard set on `close()`, `ExecutionStepInternal.reset()` defaults to a no-op with no override in `AbstractExecutionStep`, and `SelectExecutionPlan.reset()` only forwards to that no-op — so a closed plan's steps stay closed forever and re-arming restarts a dead plan, leaking cursors. The realizable shape is copy-on-re-arm via `InternalExecutionPlan.copy`, which pulls `YTDBMatchPlanStep` and `MultiPlanMatchStep` into scope.
