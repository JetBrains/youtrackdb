## Findings

### A6 [should-fix]
**Certificate**: VS5 (violation scenario, constructible), supported by AT6
**Target**: the A5 acceptance criterion at `track-9.md:147` — "`g.V().where(__.out().has(name, vadas))` … **fails before the fix**"
**Challenge**: The shape cannot fail before the fix, on the four-vertex fixture or any other, because the planner's root-selection bias routes it around the defect. The fragment commits through `commitEdgeBearingChild`: its hop lands in the parent pattern with the target registered as class `V` (`VertexHopRecogniser`'s documented contract, propagated by `MatchPatternBuilder.appendFrom:290-297`), and its `name = 'vadas'` filter lands in the parent's alias-filter map. `estimateRootEntries` then scores the target at `min(filter.estimate, classCount)` and the unfiltered origin at `classCount + 1` (`MatchExecutionPlanner:6417-6421` — the `+1` exists precisely "so that a filtered node with the same class count is preferred"), so the filtered target wins root selection unconditionally for this shape. A root alias's filter is honored today — `addPrefetchSteps` / `createSelectStatement` read it from `aliasFilters`, the mechanism the track's own Context paragraph names for the two accidental-pass shapes — so the pre-fix plan selects vadas, reverse-traverses `in()` to the origin, and returns the native single row. The watch-it-fail gate then sees a pass where the criterion promises a failure: the R16 trap, reintroduced one bullet below the criterion R16 repaired, and the fragment family is left effectively unwitnessed since a test that never failed pins nothing. The union shape in the same bullet is unaffected (its child is the track's measured 3-row traversal; 6 against native 4 pre-fix).
**Evidence**: `MatchExecutionPlanner.java:6375-6425` (`estimateRootEntries`, the min-cap and the `+1` bias comment), `:623-660` (the only estimate override applies to while-step inferred aliases, not this shape); `VertexHopRecogniser.java` javadoc ("The hop target is registered with the generic vertex class `V`"); `MatchPatternBuilder.appendFrom:288-308` (alias classes and filters merge into the parent); `ConnectiveStepSupport.commitEdgeBearingChild:69-74`; `track-9.md:54` (root filters honored — the accidental-pass mechanism); `track-9.md:146` (R16's fixture-property repair, the template this bullet omits). Reference-accuracy caveat: grep-plus-read, no PSI, no run — which is exactly why the shape must be watched to fail rather than trusted, and why a shape that cannot fail must not carry that clause.
**Proposed fix**: Replace the origin so it wins root selection and the fixture so the dropped filter changes the answer, and state the fixture property the way the `not()` criterion does. `g.V().hasLabel(person).where(__.out().has(name, vadas))` on the six-vertex modern graph works under both polymorphism modes: the origin's estimate (`count(Person)` + at most 1) undercuts the fragment target's `count(V)`-capped score, so the origin is root and the fragment filter is the dropped one; native returns `{marko}` while the dropped-filter translation returns `{marko, josh, peter}` — josh and peter are the vertices with out-edges and none to vadas, and that property is what makes the shape discriminating. A pinned-origin variant (`g.V(marko, josh, peter).where(...)`) discriminates identically if the suites prefer explicit start sets.
